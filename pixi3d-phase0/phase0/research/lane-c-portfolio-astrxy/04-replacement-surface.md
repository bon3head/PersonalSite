## 8. The WebGPU decision the fork must explicitly revisit (S00 §17)

`spec/astryx/specs/S00-foundation.md:17`: "3D | `three@0.186.1`, imported from `three` (WebGLRenderer, GLSL `ShaderMaterial`) | WebGL2 is universal; the lane field is stateless and needs no compute. WebGPU is skipped on purpose: `ShaderMaterial` and troika do not run on the WebGPU path, and past iPhone builds of this project hit WebGPU buffer limits. One path, one shader language."

Renderer semantics, normalized per independent review F2, 2026-11-12. Three separate facts, do not conflate them. 1. Architectural positioning: PixiJS 3D is designed WebGPU-first, per the open-beta blog. 2. Runtime default: omitted preference tries WebGL2 first, per the saved primary guide core-concepts-3.html.md:7-9, and a requested WebGPU path can throw rather than fall back on a GPU lacking indirect-first-instance unless the app preflights the adapter. 3. Production recommendation: Pixi v8 docs list WebGL as Recommended and stable and WebGPU as Experimental. Backend selection stays open pending target-device measurements. The fork must record, with evidence, whether the iPhone WebGPU buffer limits cited in S00 still apply to the Pixi path (different buffer layout: Pixi's batched/instanced path vs three's raw ShaderMaterial), or whether the fork stays WebGL2-first under Pixi. This is a masterspec decision, not a Lane C finding. Do not silently flip it.
