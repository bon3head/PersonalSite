## 2. Unknowns for the masterspec author (must be resolved by the appropriate lane / by Claude with evidence)

1. **Astryx 0.7.1 vs 0.7.14.** This repo pins 0.7.1. Memory says 0.7.14 is the current integration. Which version does the fork target, and who applies the upgrade? If 0.7.14, the upgrade must land as its own spec change (DESIGN.md version bump + changelog) before or alongside the Pixi work — not smuggled inside it.
2. **WebGPU vs WebGL2 for the fork.** S00 §17 skips WebGPU on purpose (ShaderMaterial + troika do not run on the WebGPU path; past iPhone builds hit WebGPU buffer limits). Pixi 3D is WebGPU-first. Does the cited iPhone buffer limit still bind under Pixi's instanced/batched path? Unknown; needs a measurement, not an argument. The fork must record the decision with the measurement attached.
3. **Lane shader language.** WGSL, GLSL, or both? The current shaders are GLSL ES 3.0 with `texelFetch` on RGBA32F textures and uniform arrays of 16. Pixi's WebGPU path needs WGSL; its WebGL2 path needs GLSL. A dual-shader fork doubles the highest-risk surface. Unknown which the masterspec chooses.
4. **Troika replacement.** No Pixi-native text path was verified in this lane. Candidates (Pixi 2D Text/BitmapText on ContainerTexture; Pixi 3D text if it exists; pre-rendered atlas) are unverified. The server scene's entire word system depends on this choice.
5. **Principal-point shift under Pixi.** `camera.ts` writes `projectionMatrix.elements[8]/[9]`. Whether Pixi's camera exposes an equivalent off-center projection is unknown in this lane. If not, poses or the readout clear-zone layout must change — and `layouts/sidequests.ts` duplicates camera projection math in pure TS (`projectToFineScreen`, `readoutClearZone`), so it must be re-verified against whatever camera ships.
6. **Color pipeline.** `lanefield.ts` deliberately uses raw sRGB values (ShaderMaterial output not color-managed; `THREE.Color` comes out dark), while `leaflink.ts` converts hex to linear. The two files disagree today. What Pixi's color management does to each path is unknown; both scenes must be re-measured, not assumed.
