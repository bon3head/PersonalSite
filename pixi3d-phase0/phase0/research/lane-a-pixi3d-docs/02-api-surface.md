# Lane A API surface: PixiJS 3D v0.1.0 on pixi.js 8.23.0

1. Format note: every entry below is one numbered line. Each claim carries its primary source URL. No claim in this file comes from a secondary source. Where a claim rests only on a one line description in an index file, the entry says so.
2. Version requirement: @pixi/3d 0.1.0 needs pixi.js ^8.23.0 as a peer dependency, and depends on meshoptimizer ^1.2.0. Source: https://registry.npmjs.org/@pixi%2F3d/latest (registry response, 2026-11-12, not saved as a file, see 01-sources.md entry 7).
3. Install command (npm): `npm install pixi.js @pixi/3d`. Source: https://pixijs.com/blog/pixi-3d-open-beta and https://3d.pixijs.download/v0.1.0/docs/getting-started-1.html.md.
4. Install command (scaffold): `npm create pixi.js@latest`. Source: https://pixijs.com/3d.
5. Install command (skills): `npx skills add https://github.com/pixijs/pixijs-skills` installs both the `pixijs` and `pixijs-3d` skills for Claude Code, Cursor, Codex, Copilot and 40 plus agents. Source: https://github.com/pixijs/pixijs-skills.
6. Install command (Claude Code marketplace): `/plugin marketplace add pixijs/pixijs-skills`. Source: https://github.com/pixijs/pixijs-skills.
7. CDN import map: map `pixi.js` to https://cdn.jsdelivr.net/npm/pixi.js@8.23.0/dist/pixi.min.mjs, `@pixi/3d` to https://cdn.jsdelivr.net/npm/@pixi/3d@0.1.0/dist/pixijs-3d.min.mjs, `@pixi/3d/extras` to https://cdn.jsdelivr.net/npm/@pixi/3d@0.1.0/dist/pixijs-3d-extras.min.mjs. Map both 3D files to the same folder and both minified or both unminified. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-1.html.md.
8. App init: `await app.init({ preference: 'webgpu' })` picks WebGPU where the browser has it and falls back to WebGL2 elsewhere. Omitting `preference` tries WebGL2 first even in a browser that has WebGPU. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-3.html.md.
9. Import order rule: import `@pixi/3d` before `app.init` runs. A renderer that started earlier never gets a backend, and a View3D on it draws nothing. This bites when 3D code arrives in a lazily loaded chunk of a 2D app that is already running. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-1.html.md.
10. Manual backend imports: with `skipExtensionImports: true`, `app.init` loads no backend, so import `@pixi/3d/webgl` and `@pixi/3d/webgpu` yourself plus the PixiJS extensions the page uses, for example `pixi.js/events`. Each imported backend goes in the main bundle. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-1.html.md.
11. TypeScript: @pixi/3d ships type declarations using the same WebGPU types as pixi.js. Types for `@pixi/3d/extras` come through the package `exports` field, so use a `moduleResolution` that reads them, such as `"bundler"`. The older `"node"` setting cannot find them. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-1.html.md.
12. View3D signature: `new View3D({ autoResize: true, environment: { skyColor: 0xc9d6ff, groundColor: 0x3a2f45 } })` then `app.stage.addChild(view3d)`. A View3D is a display object in the 2D display list. Source: https://pixijs.com/blog/pixi-3d-open-beta.
13. View3D from model: `View3D.from(source)` builds a view around a loaded glTF source, with a camera and a light. `View3D.from(source, { autoResize: true, environment: sky })` accepts view options and model options such as `castShadow` and `autoPlay` in one object. The view root is the Model3D built from the source. Source: https://pixijs.com/blog/pixi-3d-open-beta and https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
14. View3D options read from guides: `autoResize`, `environment`, `shadowQuality` (`'high'` gives sharper shadows than default and uses four times the memory), `shadowFilter`, `toneMapping`, `exposure`, `fog`, `background`, `passes`, `resolution`, `composite`, `cull`, `anchor`, `width`, `height`, `setSize`. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md and https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
15. View3D sizing rule: setting `width`, `height`, or calling `setSize` resizes the 3D viewport, not the view as a sprite would scale, and turns `autoResize` off. Default size without autoResize is 256 by 256. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
16. Multiple views: each View3D is a separate scene with its own root, camera, lights and environment. A light in one view does not light another. A node belongs to one view at a time. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
17. View3D addChild rule: everything in the scene goes under `view3d.root`. Calling `view3d.addChild` throws. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
18. 2D layering: 2D content added before the view draws behind the scene, 2D content added after it draws over it. A view has no background by default, so 2D behind shows wherever no mesh covers it. No 2D object can go between two meshes of the same view. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
19. View3D pointer catch: by default a view catches the pointer anywhere in its rectangle, even over empty space, so interactive 2D content behind it never gets the pointer. The Interaction guide covers workarounds. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started.html.md (introduction guide, one line description only for the workaround itself).
20. worldToScreen: `view3d.worldToScreen(worldPoint, outPoint)` turns a 3D world point into PixiJS global 2D coordinates, accounting for the view anchor, position, scale and rotation. Returns null for a point at or behind the camera in perspective mode. Use it to pin labels, health bars and markers to 3D objects. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
21. screenToWorld and screenToRay: `view3d.screenToWorld(event.global, plane, out)` returns where a screen ray meets a Plane, or a point a given distance from the camera when given a number. `view3d.screenToRay(point)` returns a Ray. Neither method looks at meshes. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
22. raycast: `view3d.raycast` fills a RaycastHit3D created by `createRaycastHit3D()`, for picking without events. Source: https://pixijs.com/3d/llms.txt (one line description only).
23. ContainerTexture: `new ContainerTexture({ container: ui })` draws a live 2D PixiJS Container onto a 3D surface, refreshed per frame with `face.render(app.renderer)` in the ticker. Nesting works: a 2D container can hold its own View3D, as many levels deep as wanted. Source: https://pixijs.com/3d and https://pixijs.com/blog/pixi-3d-open-beta.
24. Filters and masks on a view: PixiJS filters and masks work on a View3D or on a 2D container holding one. Create filters on a view with `antialias: 'inherit'` and `resolution: 'inherit'` or the view loses sharpness and antialiasing on a high resolution canvas. `view3d.alpha` and `view3d.tint` do not fade or tint a view; use AlphaFilter or ColorMatrixFilter. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-1.html.md.
25. Scene graph axes: +X right, +Y up, +Z out of the screen toward the viewer with an unrotated camera. Camera and directional or spot lights look and shine along local -Z. A mesh front is its +Z side. One unit is one metre by default; camera far plane defaults to 1000. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts.html.md.
26. Container3D: base node class, the 3D counterpart of pixi.js Container. Meshes, models, cameras and lights are all Container3Ds. Constructor takes Container3DOptions such as `position`, `rotation`, `label` plus its own options. Methods include `addChild`, `removeFromParent`, `getChildByLabel(label, recursive)`, `getGlobalPosition(out)`, `toGlobal`, `toLocal`, `lookAt(point)`, `reparentChild(child)`, `logHierarchy()`. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts.html.md and https://pixijs.com/3d/llms.txt.
27. Rotation versus quaternion: a node uses whichever of `rotation` or `quaternion` was set last. `lookAt`, loaded models and their animations set the quaternion. `rotation.y += 0.1` on a node whose orientation lives in the quaternion replaces the file rotation. Setting `rotation` to values it already holds changes nothing. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts.html.md.
28. Rotation order: when more than one angle is set, the node turns around Z first, then Y, then X, each around its parent axes. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts.html.md.
29. Mesh3D signature: `new Mesh3D({ geometry, material })` where geometry is a Geometry3D and material is a BaseMaterial3D. Meshes cast and receive shadows by default. Source: https://pixijs.com/blog/pixi-3d-open-beta and https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
30. Built-in geometries (nine): CapsuleGeometry, ConeGeometry, CubeGeometry, CylinderGeometry, IcosahedronGeometry, PlaneGeometry, SphereGeometry, TorusGeometry, TorusKnotGeometry, all plus Geometry3D for custom vertex data. PlaneGeometry lies in the XY plane facing +Z; rotate -PI/2 around X to lay it flat facing up. Source: https://pixijs.com/3d/llms.txt and https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md.
31. Model3D signature: `new Model3D(source)` or `new Model3D({ source, materials, castShadow, receiveShadow, autoPlay })`. A Model3D is a Container3D built from a loaded glTF file, a Scene3DSource. Source: https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
32. Assets loading: `const source = await Assets.load<Scene3DSource>('car.glb')`. Importing @pixi/3d registers .gltf and .glb loaders with Assets. Each Model3D built from one source shares its geometry, materials and textures. Source: https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
33. Model materials: `source.material['Paint']` holds the file named materials keyed by name. `new Model3D({ source, materials: { Paint: source.material['Paint'].clone({ baseColor: 0xd81b3c }) } })` gives one model its own materials. Assigning `model.materials` switches materials on a built model; assigning undefined restores the source materials. Source: https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
34. Model contents: a glTF mesh with one part becomes a Mesh3D; with several parts it becomes a Container3D holding one Mesh3D per part. Nodes take the file name as `label`, or `node_<index>`. File cameras become Camera3D nodes in `model.cameras`. File lights become DirectionalLight, PointLight and SpotLight nodes. Source: https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
35. Model cleanup: `car.destroy({ children: true })` then `await Assets.unload('car.glb')` frees a file. `car.unload()` frees GPU memory while keeping the model, but unloads the shared source geometry and materials, so remove all models built from that source first. Source: https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
36. glTF extensions read: KHR_materials_clearcoat, KHR_materials_sheen, KHR_materials_specular, KHR_materials_iridescence, KHR_materials_anisotropy, KHR_materials_ior, KHR_materials_transmission, KHR_materials_volume, KHR_materials_emissive_strength, KHR_materials_unlit, KHR_texture_transform, KHR_texture_basisu, EXT_texture_avif, EXT_texture_webp, KHR_lights_punctual, KHR_node_visibility, KHR_draco_mesh_compression, EXT_meshopt_compression, KHR_meshopt_compression, KHR_mesh_quantization. Source: https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
37. Compressed models: meshopt, Draco and mesh quantization are supported; compress your own with gltfpack. Draco decoder defaults to Google hosted build; `setDracoDecoderPath` self-hosts it. KTX2 textures need `import 'pixi.js/ktx2'` once before loading, or a texture with only a KTX2 image fails the load. Source: https://pixijs.com/3d/llms.txt and https://3d.pixijs.download/v0.1.0/docs/assets.html.md.
38. Material3D (PBR): `new Material3D({ baseColor: 0xdd4444, roughness: 0.5 })`. Roughness runs 0 for mirror-like to 1 for fully rough. Options include baseColor, metallic, roughness, normal and occlusion maps, emissive as an opt-in group `emissive: { color, strength }`, clearcoat, sheen, specular, index of refraction, iridescence, glass via transmission, anisotropy, alphaMode, doubleSided, uvTransform. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md and https://pixijs.com/3d/llms.txt (physical extensions entry, one line description only).
39. Other materials: PhongMaterial is Blinn-Phong diffuse plus specular highlight. FlatMaterial is unlit, draws base colour and texture with no lighting. ToonMaterial in extras is cel-shaded with banded diffuse, sharp specular and rim light. PortalMaterial in extras is an unlit surface showing a render-texture feed. Source: https://pixijs.com/3d/llms.txt.
40. Material alpha modes: `alphaMode` defaults to `'opaque'`, which ignores `alpha` and texture alpha. Three.js `transparent: true` becomes `'blend'`, alphaTest becomes `'mask'` with `alphaCutoff`. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-3.html.md.
41. Lights (four types): DirectionalLight (parallel, like the sun), PointLight (every direction from a point, like a bulb), SpotLight (cone from a point, like a torch), AmbientLight (same light on every surface, from no direction). All are Container3Ds under view3d.root. With no lights and no environment, a Material3D mesh draws black. Source: https://3d.pixijs.download/v0.1.0/docs/scene-4.html.md.
42. DirectionalLight signature: `new DirectionalLight({ color: 0xfff4e0, intensity: 3, castShadow: true })`, position set then `sun.lookAt({ x: 0, y: 0, z: 0 })`. Lights have no target; directional and spot lights shine along local -Z, so call lookAt after placing one and again after every move. Source: https://pixijs.com/blog/pixi-3d-open-beta and https://3d.pixijs.download/v0.1.0/docs/scene-4.html.md.
43. Light intensity rules: intensities above 1 are normal; under default toneMapping `'none'`, a white Material3D surface facing a directional light of intensity 1 shows mid grey, intensity about 3 brings it to white. Point and spot lights dim with the square of distance. Hemisphere environment intensity ports from Three.js divided by PI. Source: https://3d.pixijs.download/v0.1.0/docs/scene-4.html.md and https://3d.pixijs.download/v0.1.0/docs/getting-started-3.html.md.
44. Light limit: a view shades at most 32 directional, point and spot lights (MAX_LIGHTS). Ambient and hidden lights do not count. Past the limit the view leaves out the visible lights that come last in `view3d.lights`, with no warning. Source: https://3d.pixijs.download/v0.1.0/docs/scene-4.html.md.
45. PointLight and SpotLight range: `new PointLight({ color: 0xffd180, intensity: 8, range: 12 })`. Without a range a light shades every lit pixel. SpotLight adds `coneAngle` (degrees from centre to edge, whole cone is twice that) and `penumbra` 0 to 1. Point lights cast no shadows; use a spot light for a lamp that casts a shadow. Source: https://3d.pixijs.download/v0.1.0/docs/scene-4.html.md.
46. Shadows on: set `castShadow: true` on a DirectionalLight or SpotLight. Meshes cast and receive by default, so set `castShadow: false` on floors and terrain or the sun shadow box stretches and blurs. Blended (`alphaMode: 'blend'`) or transmissive materials cast no shadow. Source: https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
47. Shadow bounds and cascades: by default the light fits its shadow box around every visible shadow caster, refitting each redraw while the scene has 256 casters or fewer. `sun.shadow.bounds = Box.fromCenterSize({ x: 0, y: 1, z: 0 }, { x: 14, y: 2.6, z: 14 })` sets a manual box in world coordinates. `sun.shadow.cascades = 3` with `sun.shadow.maxDistance = 80` splits the camera view into 1 to 4 slices by distance. Source: https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
48. Shadow redraw: `shadow.update` takes a number N for every Nth frame, `'manual'` for redraw only on `light.refreshShadows()`, or an array giving each cascade its own rate, for example `[1, 2, 8]`. Source: https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
49. Shadow map limit: all lights in a view share 16 shadow maps. Each spot light and each directional light without cascades takes one; a cascaded light takes one per cascade. A light that does not fit still lights the scene but without its shadow, with a warning. Source: https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
50. Shadow bias: `shadow.bias` has the opposite sign to Three.js, so negate a Three.js value or keep the default. `shadow.mapSize` becomes the view `shadowQuality`; the shadow camera box becomes `shadow.bounds` in world space. Acne is fixed by raising bias or normalBias; too much bias causes peter-panning. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-3.html.md and https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
51. Cameras: every view comes with a Camera3D at `view3d.camera`. Default field of view 60, far plane 1000. Set `view3d.camera.fov`, `view3d.camera.far`, `view3d.camera.position`. Mode is perspective by default or orthographic. Second cameras draw the scene from a second angle into a renderTexture for monitors, sprites or portals. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md and https://pixijs.com/3d/llms.txt (cameras and second cameras entries, one line descriptions only).
52. OrbitCamera: `new OrbitCamera({ view: view3d, target: { x: 0, y: 0.4, z: 0 }, enableDamping: true, minDistance: 2, maxDistance: 15 })` from `@pixi/3d/extras`. Drag to orbit, scroll or pinch to zoom. Starts from where the camera is and always turns it to face the target. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md.
53. FPSCamera: first-person controller for a View3D camera, from `@pixi/3d/extras`. Mouse, touch and keyboard controls. Source: https://pixijs.com/3d/llms.txt (one line description only).
54. Environment and IBL: `new View3D({ environment: { skyColor, groundColor, intensity } })` uses a Hemisphere gradient. A cube map environment lights from an image of surroundings. Tone mapping, exposure and fog live on the view. Exposure scales light even under toneMapping `'none'`, where Three.js ignores it. Source: https://pixijs.com/3d/llms.txt and https://3d.pixijs.download/v0.1.0/docs/getting-started-3.html.md.
55. Animation: a model `player` plays clips by name, for example `fox.player?.play('Walk')`, or `autoPlay: 'Walk'` in Model3D options. AnimationPlayer plays and blends clips on a Container3D and its children; AnimationState holds playback state for one Animation with a `weight` for blending. Morph target weights and keyframe animations in code are supported. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md and https://pixijs.com/3d/llms.txt.
56. Sprite3D: textured card that turns to face the camera by default. Casts no shadow by default and blends by default; casts only with `castShadow: true` and alphaMode `'mask'` or `'opaque'`. Source: https://pixijs.com/3d/llms.txt and https://3d.pixijs.download/v0.1.0/docs/scene-5.html.md.
57. BatchedMesh3D: draws thousands of meshes from one node, with slots, matrices, hidden spares, camera-facing cards, culling and cleanup. A slot casts only when turned on with `setPassesAt`. Its `cull` is off by default. Example scale in the blog: 100,000 objects with shadows at 60 fps; the performance guide scales to 25,000 slots on phones and tablets versus 100,000 on desktop. Source: https://pixijs.com/blog/pixi-3d-open-beta and https://3d.pixijs.download/v0.1.0/docs/core-concepts-5.html.md.
58. Auto-batching: meshes sharing the same Geometry3D object, the same shader and state, and the same texture sources draw in one instanced draw call. Values such as colours, roughness and transforms do not split the call. On WebGPU each material among them takes its own call, so share one material between meshes that look the same. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-5.html.md.
59. Culling: view `cull` mode defaults to `'gpu'`. On WebGPU it runs in a compute shader, except in Safari and on any iPhone or iPad where it runs on the CPU for a typical scene and moves to the compute shader only once a batch gets big enough. On WebGL2 it runs on the CPU. Blended meshes are tested on the CPU on both renderers. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-3.html.md and https://pixijs.com/blog/pixi-3d-open-beta.
60. Particles: ParticleSystem3D from `@pixi/3d/extras` emits fire, smoke, sparks and snow from one options object, with emission, lifetimes, spreads, forces and over-life ramps. Shapes are PointShape (default), BoxShape, ConeShape, SphereShape. ParticleContainer3D is a fixed pool of camera-facing quads drawn in one call, moved by user code. Source: https://pixijs.com/3d/llms.txt and https://pixijs.com/3d.
61. Post-processing effects (all from `@pixi/3d/extras`, added to `view3d.passes`): BloomEffect (beforeToneMapping, threshold default picks parts brighter than white), SsaoEffect (beforeToneMapping, radius in world units), TiltShiftEffect (beforeToneMapping, focalDepth is distance straight out from the camera), MotionBlurEffect (beforeToneMapping, blurs only by camera motion), FxaaEffect (afterToneMapping), TintEffect (afterToneMapping). Set `effect.enabled = false` to stop one; changing `enabled` rebuilds the render graph, so do not toggle every frame. Source: https://3d.pixijs.download/v0.1.0/docs/extras_post-processing.html.md.
62. OutlinePass and WireframePass: MeshPass entries in the same `passes` list. OutlinePass draws opted-in meshes again as ink outlines; a mesh joins by the pass name via its material `passes` option or `enablePass`. WireframePass redraws opted-in meshes as lines. PortalPass is a texture portal showing a second view of the scene. Source: https://3d.pixijs.download/v0.1.0/docs/extras_post-processing.html.md and https://pixijs.com/3d/llms.txt.
63. Custom post effect: subclass PostEffect with a `fragment` holding both WGSL (`gpu`) and GLSL (`gl`) code for `effect(uv)`, using `sampleColor(uv)`, `sampleDepth(uv)` and `viewPos(uv)` helpers. Uniforms are read as `fx.<name>` in WGSL and plain `<name>` in GLSL. Source: https://3d.pixijs.download/v0.1.0/docs/extras_post-processing.html.md.
64. Custom materials and render graph: write your own materials, shader code and post effects, or build a custom render graph with PassBuilder, RenderGraph and createDefaultGraph3D. A ShaderBit holds its code twice, `gpu` in WGSL and `gl` in GLSL; a bit lacking one runs none of its code on that renderer, with no error. Source: https://pixijs.com/blog/pixi-3d-open-beta and https://3d.pixijs.download/v0.1.0/docs/core-concepts-3.html.md.
65. Events on 3D objects: set a node `eventMode` (for example `'static'`) and `cursor`, then listen as in 2D, for example `mesh.on('pointertap', () => spin(mesh))`. Pointer events are ray-picked with the same names, bubbling and cursors as 2D. Source: https://pixijs.com/3d.
66. Ticker time: `app.ticker.add((ticker) => { cube.rotation.y += 0.5 * (ticker.deltaMS / 1000); })`. `ticker.deltaTime` measures time in 60 fps frames, not seconds; use `ticker.deltaMS / 1000` for seconds. The ticker caps `deltaMS` at 100 ms, so below 10 fps motion slows down. OrbitCamera, a model player and ParticleSystem3D advance on Ticker.shared unless stepped manually with `autoUpdate: false` and an explicit `update(ticker)` call. Source: https://3d.pixijs.download/v0.1.0/docs/getting-started-2.html.md and https://3d.pixijs.download/v0.1.0/docs/getting-started-3.html.md.
67. Performance checklist (phone): cap app resolution at 2, lower View3D resolution alone to keep 2D sharp, turn off antialias if a phone still drops frames, choose view settings before first render because toneMapping and similar settings compile new shaders, prefer Hemisphere over a cube map environment, turn off castShadow on floors, redraw shadows less often, set shadowFilter to `'hard'`, give point and spot lights a range, use alphaMode `'mask'` over `'blend'` for hard edges, use FlatMaterial where no lighting is needed, keep shapes drawn thousands of times simple, load compressed models, hide meshes with `visible` rather than removing them, do not create objects in the ticker, keep post effects few, test on WebGL2 too. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-5.html.md.
68. WebGPU feature gate: on WebGPU, PixiJS 3D needs a GPU with the `'indirect-first-instance'` feature. On a GPU without it, `app.init` throws instead of falling back to WebGL2. Check first with `navigator.gpu?.requestAdapter()` and `adapter?.features.has('indirect-first-instance')`, then choose `'webgpu'` or `'webgl'`. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-3.html.md.
69. WebGL2 float texture gate: features drawing into floating-point textures, including cube map environments and any post effect whose stage is `'beforeToneMapping'`, render only when the device has the `EXT_color_buffer_float` extension. Rendering throws on a device without it. Without the extension a Hemisphere environment still lights the scene but loses reflections, so a metal surface with no other light turns black. Source: https://3d.pixijs.download/v0.1.0/docs/core-concepts-3.html.md.
