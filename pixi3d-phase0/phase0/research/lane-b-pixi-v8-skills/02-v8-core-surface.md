3D docs pinned version: v0.1.0 (`https://3d.pixijs.download/v0.1.0/docs/`, via `https://pixijs.com/3d/llms.txt`).
All claims below trace to sources in 01-sources.md. No guessing; gaps are in 04-limits-unknowns.md.

## 1. Application

- `Application` is the convenience wrapper owning a renderer, a root `stage` Container, a canvas, and the Ticker / Resize plugins.
- Lifecycle is async and is the v8 number-one gotcha: `const app = new Application(); await app.init({ ... })`. Constructor takes no arguments; v7 `new Application({ ... })` options are ignored with a deprecation warning.
- Until `init` resolves, `app.renderer` is `undefined` and `app.canvas` / `app.screen` throw. All renderer-dependent work goes after `await app.init()`.
- `app.stage` is the root Container. `app.screen` is the visible area in CSS pixels. `app.view` is renamed `app.canvas` in v8 (old getter still works but warns).
- Init options used in fetched examples: `resizeTo: window`, `background` / `backgroundColor`, `antialias: true`, `autoDensity: true`, `resolution: window.devicePixelRatio`, `preference: 'webgpu' | 'webgl' | 'canvas'` (also an array form, e.g. `['webgl', 'canvas']` to exclude WebGPU).
- Renderer selection: `autoDetectRenderer({ preference })`. Rendering doc: WebGLRenderer is default, Recommended, stable and widely supported; WebGPURenderer is Experimental, feature-complete but browser inconsistencies may cause unexpected behaviour, use WebGL for production; CanvasRenderer is Experimental fallback. Note the tension with the 3D blog (WebGPU first): the v8 rendering doc is the conservative production statement; the 3D skill states `app.init` uses WebGL unless `preference: 'webgpu'` is passed.
- Resize: `resizeTo` at init (or reassigned later) makes ResizePlugin call `renderer.resize()` with the target size. Window resize is applied on the next animation frame, so a personal `window` resize listener still reads the old `app.screen`; lay out from `app.renderer.on('resize', (w, h) => ...)`. An element target needs `new ResizeObserver(() => app.queueResize())`. `resizeTo` does not work in a Web Worker.
- Resolution after init: runtime flag lives on `app.renderer.view.autoDensity`; `renderer.resize(w, h, resolution)` sets backing store to `w * resolution` while `app.screen` stays in logical pixels and emits `resize`. `app.renderer.autoDensity` does not exist. Lay out with `app.screen`, not `app.canvas.width` (device pixels).
- Render loop: TickerPlugin creates `app.ticker`, registers `app.render()` on it, adds `app.start()` / `app.stop()`. `autoStart: false` only leaves the ticker stopped; a manual loop calls either `app.ticker.update(time)` or `app.render()`, never both.
- CullerPlugin is opt-in: `extensions.add(CullerPlugin)` before `app.init()` makes every render cull `app.stage` against the screen; only objects with `cullable = true` are culled.
- Custom Application plugins: class with `static extension = ExtensionType.Application` and static `init` / `destroy`, `this` bound to the Application. Plugins initialise in descending `extension.priority`, destroy in reverse.
- Teardown: `app.destroy()` throws if `init` has not resolved; in React StrictMode / fast unmounts chain destroy on the init promise. `app.destroy({ removeView: true, releaseGlobalResources: true }, { children: true, texture: true, textureSource: true })` is the full form in the skill. `releaseGlobalResources` drains global pools; without it a recreated app in the same tab reuses pooled batches/textures (flicker / stale textures). Textures from `Assets.load` stay in the Assets cache; release with `Assets.unload(...)`, not via destroy flags. There is no teardown event: Application is not an event emitter.
- Vite trap (skill): top-level `await` fails `vite build` on Vite 6 and older; wrap init in an async IIFE. Run `npx tsc --noEmit` to catch wrong option names; a Vite build does not type-check.

## 2. Assets

- `Assets` is the global singleton for loading, caching, and unloading. Promise-based, caches automatically, picks best file format for the device. Most projects use `Assets.load()` as first step after creating an Application.
- `await Assets.init({ basePath, manifest })` before the first `load`, `loadBundle`, or `backgroundLoad`; a later `init` is dropped.
- Supported types (from docs table): textures `.png .jpg .jpeg .gif .webp .avif .svg`; video textures `.mp4 .m4v .webm .ogg .ogv .h264 .avi .mov`; spritesheets `.json`; bitmap fonts `.fnt .xml`; web fonts `.ttf .otf .woff .woff2`; JSON `.json`; text `.txt`; compressed textures `.basis .dds .ktx .ktx2`. Custom parsers via LoaderParser.
- Load forms: `await Assets.load<Texture>('bunny.png')` (single); `await Assets.load(['a.png', 'b.json'])` resolves to an object keyed by URL or alias — read `res[a]`; `await Assets.load({ alias: 'bunny', src: '...' })` then `Assets.get('bunny')`.
- Repeated loads are safe: same URL/alias returns the same instance (`p1 === p2` is true).
- Bundles: `Assets.addBundle('loading-screen', [{ alias, src }, ...])`, then `await Assets.loadBundle('loading-screen')`. Manifest-based bundles are the larger-app path; AssetPack automates manifests.
- Background loading: `Assets.backgroundLoad([...])`; later `Assets.load` resolves immediately if already loaded.
- Load options / strategies: `onProgress(progress 0–1)`, `onError(error, asset)`, `strategy: 'throw' | 'skip' | 'retry'`, `retryCount` default 3, `retryDelay` default 250 ms. `throw` rejects on first failure; `skip` ignores failures (onError still fires); `retry` retries each failing asset then throws. Set globally via `Assets.init({ loadOptions })` or per call.
- Config: `Assets.init({ basePath, texturePreference: { format: ['webp', 'png'], resolution: 2 }, defaultSearchParams, skipDetections, manifest, preferences, bundleIdentifier, loadOptions })`.
- Cache: `Assets.cache.has(...)`, `Assets.get(...)`, `await Assets.unload(...)`, `Assets.reset()`.
- Traps (skill): a URL with no file extension (`?id=`, `blob:`, API route) needs `Assets.load({ src, parser: 'texture' })`; without it the result is `null` with only a warning. Audio files have no loader and also resolve `null`; play sound with `@pixi/sound` or `HTMLAudioElement`. `Texture.from(url)` / `Sprite.from(url)` read the cache only in v8 (v7 fetched): `await Assets.load(url)` first. Per-asset `data` (`scaleMode`, `resolution`) applies on first load of a `src` only; set `texture.source.scaleMode` on the result instead. Do not `Assets.unload` while live sprites still reference the asset (secondary corroboration; skill router lists it under assets).

## 3. Stage / Container / scene graph

- The scene graph is a tree rooted at `app.stage`. Parent position / rotation / alpha flow down to children (alpha multiplies: parent 0.5 × child 0.5 = 0.25). Cumulative transform is `worldTransform`, cumulative alpha is `worldAlpha`.
- `Container` groups display objects; it draws nothing itself. Children render in insertion order; second child draws over first.
- Children API: `addChild(...children)`, `removeChild`, `addChildAt`, `swapChildren`, `removeChildAt`, `removeChildren`, `reparentChild` / `reparentChildAt` (keeps world transform; plain `addChild` keeps local numbers, so the child jumps to the same offset under the new parent).
- Finding children: `getChildByLabel(label)`, `getChildrenByLabel(regex)`, `deep = true` for recursive search. Labels are set via `new Container({ label: 'enemy' })`.
- Lifecycle events: parent-side `childAdded` / `childRemoved`; child-side `added` / `removed`; `visibleChanged`; `destroyed` (fires after internal cleanup, before listeners removed). `addChildAt` repositioning within the same container fires no add/remove events.
- Order: `zIndex` orders siblings only and sorts at next render; set `container.sortableChildren = true` and call `sortChildren()` before reading `children` if order matters. Sorting is expensive for large child counts.
- Depth-sort across parents: `new RenderLayer({ sortableChildren: true })` + `layer.attach(obj)`; attach again after reparenting; the layer's own `visible` / `alpha` / position do nothing — hide or move the objects themselves.
- Render groups: `isRenderGroup = true` or `enableRenderGroup()` isolates a container's rendering instructions so the GPU transforms the whole group without recalculating each child. Good candidates: UI layers over a game world, large subtrees moving as a unit, particle systems.
- `cacheAsTexture`: draws a container and children to a single texture; later renders reuse it. v8 equivalent of v7 `cacheAsBitmap`. Call `updateCacheTexture()` after children change; a `cacheAsTexture(true)` container shows child changes only after that call.
- Culling: `sprite.cullable = true`, `container.cullableChildren = false` to skip recursive child culling, `sprite.cullArea = new Rectangle(...)` to avoid measuring each frame.
- Coordinates: local (relative to parent), global (relative to stage origin, top-left), screen/viewport (relative to canvas element). `toGlobal(point)`, `toLocal(point)`, `getBounds()` returns `Bounds` — hit-test with `getBounds().rectangle.contains(x, y)`.
- Hiding: `visible = false` and `renderable = false` remove an object from hit testing; an invisible hit target uses `alpha = 0` or a `hitArea`.
- Destroy: `destroy({ children: true })` for a subtree; `destroy(true)` also destroys shared textures, atlases, and GraphicsContexts, and every later render of another user throws. Destroy textures created by the app (`generateTexture`, canvases) with `texture.destroy(true)`; defer a destroy from inside `onRender` with `app.ticker.addOnce(() => obj.destroy())`.

## 4. Ticker

- `Ticker` executes callbacks every animation frame, with priority ordering and frame-rate control. `app.ticker` is the Application ticker; `Ticker.shared` is the global instance the Application uses by default.
- Callback signature: `app.ticker.add((ticker) => { sprite.rotation += 0.01 * ticker.deltaTime; })`. The callback receives the `Ticker`, not a bare delta.
- Time units: `deltaTime` is a frame-rate-independent multiplier, ~1.0 at 60 fps, affected by `speed`; `deltaMS` is real milliseconds since last frame, not affected by `speed`; `elapsedMS` is milliseconds spent processing the last frame; `FPS` is current frames per second; `lastTime` is the timestamp of the last frame.
- Priority: `UPDATE_PRIORITY.HIGH = 50`, `NORMAL = 0`, `LOW = -50`. Higher runs earlier. `app.render()` is registered at `LOW` by TickerPlugin. Read canvas pixels from a listener at `UPDATE_PRIORITY.UTILITY`, which runs after the render.
- FPS control: `minFPS` caps how large `deltaTime` can get (e.g. 30 → deltaTime will not exceed ~2.0 even if a frame takes 500 ms); `maxFPS` limits how fast the ticker runs (0 = unlimited). The two clamp each other automatically.
- Speed: `ticker.speed = 0.5` (half speed) / `2.0` (double speed) scales time for all listeners at once.
- Per-object frame logic: `obj.onRender = () => { ... }` (replaces v7 `updateTransform` overrides); it also runs while the object is invisible. Do not name subclass methods `_onRender`.
- `app.ticker.update()` already renders, even with `autoStart: false`; skip the extra `app.render()`.
- Cleanup: `ticker.stop()`, `ticker.remove(myCallback)`, `ticker.destroy()`. Remove ticker callbacks when their scene is destroyed. `AnimatedSprite` runs on `Ticker.shared`, so `app.ticker.stop()` does not pause it.
- 3D ordering note (from pixijs-3d skill): `OrbitCamera`, `FPSCamera`, `ParticleSystem3D`, and a model's animation `player` update themselves on `Ticker.shared`, not `app.ticker`, so their step can land after the frame's code or a frame late. Pass `autoUpdate: false` and call `update(ticker)` from the `app.ticker` callback when order matters.

## 5. Filters, blend modes, masks

- Filters apply post-processing to any display object and its children: blur, color adjustments, noise, displacement, custom shaders.
- Built-in filters (five): `AlphaFilter`, `BlurFilter` (Gaussian, `strength` default 8, `quality` default 4, `kernelSize` default 5, `strengthX` / `strengthY`), `ColorMatrixFilter` (5×4 matrix, presets including `brightness`, `contrast`, `saturate`, `greyscale`, `hue`, `negative`, `sepia`, `night`, `predator`, `lsd`, `reset`), `DisplacementFilter` (`{ sprite, scale }`, sprite must be on the stage, animate by moving that sprite, map texture `addressMode = 'repeat'`), `NoiseFilter` (`noise` default 0.5, `seed`).
- Assignment: `sprite.filters = new BlurFilter({ strength: 8 })` or an array, applied in array order. Assign a new array to change filters: `c.filters = [...(c.filters ?? []), blur]`. Set `sprite.filters = null` to skip filter processing.
- Filter options: `blendMode` (default `'normal'`), `resolution` (default `1`, or `'inherit'`), `padding` (default 0), `antialias` (default `'off'`), `blendRequired`, `clipToViewport` (default true). Effects reaching past the shape (glow, wave, outline) need `padding`; a full-screen stage filter needs `app.stage.filterArea = app.screen`; use `resolution: 'inherit'` on a high-DPI renderer.
- Performance: limit filter area with `sprite.filterArea = new Rectangle(...)`; share filter instances across objects; lower BlurFilter `quality`; full-screen blur padding pushes the texture past screen size to the next power of two — set `repeatEdgePixels: true` on a full-screen blur to keep it screen-sized. Prefer baked sprite sheets for static effects.
- Custom filters: `Filter.from({ gl: { vertex, fragment }, resources })`. v8 uses GLSL ES 3.0 (`in`/`out`, `texture()`, `out vec4 finalColor`, not `gl_FragColor` / `texture2D`). In the fragment, sample `uTexture`, get 0–1 coordinates from `vTextureCoord * uInputSize.xy / uOutputFrame.zw` (both `highp`), keep colour premultiplied. Uniforms declared in `resources` are accessible at `filter.resources.<group>.uniforms.<name>`. For dual-renderer support include both a `glProgram` and a `gpuProgram`. WebGPU trap: on the WebGPU renderer every filter needs a `gpu` program too, or all filters on that container are skipped. The Canvas renderer skips filters.
- Advanced blend modes: separate side-effect import `import 'pixi.js/advanced-blend-modes'`; then `sprite.blendMode = 'color-burn'` etc. Modes beyond `normal` / `add` / `multiply` / `screen` / `erase` / `min` / `max` need that import and, on WebGL, `app.init({ useBackBuffer: true })`. A filtered container composites with its last filter's `blendMode`.
- Erase / paint: the render root's own `blendMode` is ignored — put an `'erase'` brush inside a plain `Container` and pass the wrapper to `renderer.render({ container: wrapper, target, clear: false })`; `clear: false` keeps earlier strokes. `'erase'` clears everything under it in the same target, background included; give the erasable layer its own `RenderTexture`. Brush coordinates are texture pixels: `sprite.toLocal(e.global)` plus the anchor offset.
- `generateTexture({ target, frame: new Rectangle(...) })`: `frame` must be a real `Rectangle` (a plain object throws `copyTo is not a function`), and the capture ignores the target's own position, scale, and rotation.
- Masks (skill-level, not a standalone doc fetched): add a mask as a child of the masked `Container`; a `Sprite` mask reads the red channel unless `setMask({ mask, channel: 'alpha' })`. Mask sub-pages live under `scene-core-concepts` in the skill (`mask`, `setMask`, inverse, sprite-mask channel). Standalone mask doc page was not fetched — see 04.
- 3D post-processing (from pixijs-3d skill / 3D llms.txt): `BloomEffect`, `SsaoEffect`, `FxaaEffect`, `TiltShiftEffect`, `MotionBlurEffect`, `TintEffect`, `OutlinePass`, `PortalPass`, `WireframePass`, from `@pixi/3d/extras`, via `view.passes`. Bloom threshold is 1 in linear light: glowing things need `emissive` with `strength` above 1; a threshold near 0.5 blooms every lit surface. MSAA carries through effects, so add `FxaaEffect` only without `antialias`. Toggle effects with `enabled`; adding the first or removing the last pre-curve effect recompiles every material.

## 6. Pointer events

- Federated event model: DOM-like, with bubbling, capturing, and delegation across the scene graph. Pointer events are recommended for cross-device compatibility.
- `eventMode` values: `none` (ignores all events, including on children, optimised for non-interactive elements); `passive` (default — does not respond itself, interactive children still receive events); `auto` (clickable only when a parent is interactive); `static` (emits events and is hit tested — stationary elements like buttons); `dynamic` (same as `static`, plus pointer-overlap check every frame via the ticker, even when the pointer is not moving — moving/animating objects under a stationary cursor).
- Rule: give every listening object `eventMode = 'static'` and `cursor = 'pointer'` (v7 `buttonMode`). Default `'passive'` never fires its own listeners.
- Pointer events: `pointerdown`, `pointerup`, `pointerupoutside`, `pointermove`, `pointerover` (bubbles), `pointerout` (bubbles), `pointerenter` / `pointerleave` (do not bubble), `pointercancel`, `pointertap`, `globalpointermove` (fires on every move regardless of hit target). Buttons listen to `pointertap` (`click` is mouse only, `tap` touch only); a double click is `e.detail === 2`.
- Mouse events: `mousedown`, `mouseup`, `mouseupoutside`, `mousemove`, `mouseover` / `mouseout`, `mouseenter` / `mouseleave`, `click`, `rightdown` / `rightup` / `rightupoutside` / `rightclick`, `contextmenu`, `globalmousemove`, `wheel`. Touch events: `touchstart`, `touchend`, `touchendoutside`, `touchmove`, `touchcancel`, `tap`, `globaltouchmove`.
- v8 breaking change: `pointermove` / `mousemove` / `touchmove` now fire only when the pointer is over a display object. In v7 they fired on any canvas move. Use `globalpointermove` / `globalmousemove` / `globaltouchmove` for every-move behaviour.
- Drag pattern: drag with `globalpointermove` (plain `pointermove` fires only over the object), end on `pointerup` and `pointerupoutside`, convert with `parent.toLocal(e.global)`, keep points with `p.copyFrom(e.global)` (event objects are reused).
- Hit testing: PixiJS walks the display tree to the top-most interactive element under the pointer. `eventMode: 'none'` skips element and children; `interactiveChildren: false` skips children; a set `hitArea` overrides bounds-based testing; not-visible / not-renderable / not-measurable objects are skipped. Custom hit areas: `Rectangle`, `Circle`, `Polygon`, or `{ contains(x, y) }`.
- Empty-canvas clicks: `app.stage.eventMode = 'static'` and `app.stage.hitArea = app.screen`. A plain `Container` is hit only on its children; give it a `hitArea` to cover gaps.
- Capture phase: append `capture` to the event name (`pointerdowncapture`), or `addEventListener(..., { capture: true })`. `stopImmediatePropagation()` blocks the event from reaching children.
- Context menu: PixiJS does not block the browser menu; call `event.preventDefault()` in a `contextmenu` listener. Cancelling `rightdown` / `rightup` / `rightclick` does not keep it closed.
- Wheel: stop page scroll with a native `app.canvas.addEventListener('wheel', (e) => e.preventDefault(), { passive: false })`.
- Listening styles: `on()` / `off()` / `once()` (EventEmitter style, recommended), `addEventListener()` / `removeEventListener()` (DOM style), property callbacks (`sprite.onclick = ...`).
- `isInteractive()` returns true when `eventMode` is `'static'` or `'dynamic'`.
- Event features toggle: `app.init({ eventFeatures: { move, globalMove, click, wheel } })`, all default true; or `app.renderer.events.features.globalMove = false` after init.
- Cursor: `sprite.cursor = 'pointer' | 'grab' | 'url("custom.png"), auto'`; named cursor styles can be registered on `app.renderer.events.cursorStyles`.
- Performance: `eventMode = 'none'` on non-interactive elements, `interactiveChildren = false` where only the container needs interaction, `hitArea` for large/complex objects, `'static'` for stationary elements, disable unused event features.
- 3D picking (from pixijs-3d skill): 3D nodes default to `eventMode: 'passive'` — set `'static'` (also a `Mesh3D` option) or nothing picks. `pointertap` fires for every mouse button, so check `e.button`. A full-screen view hit-tests its whole rectangle and blocks clicks to 2D objects behind it: put interactive 2D above the view or set `view.hitArea`.

## 7. Text and sprites

- Sprite: displays a single image (texture). `const texture = await Assets.load('path/to/image.png'); const sprite = new Sprite(texture); sprite.anchor.set(0.5); sprite.position.set(100, 100); sprite.scale.set(2); sprite.rotation = Math.PI / 4;`
- `scale` is a multiplier relative to texture size; `width` / `height` are absolute pixel setters that compute the corresponding scale. Setting `width` recalculates `scale.x` and vice versa. Changing `sprite.texture` rebinds listeners, recalculates width/height so visual size stays the same, and triggers a visual update.
- Sprite vs neighbours: use `Sprite` for a single image / spritesheet frame; `TilingSprite` for repeating textures; `NineSliceSprite` for scalable UI panels with preserved corners/edges.
- Sprite traps (skill): wrap a `TextureSource` (`CanvasSource`, `texture.source`) as `Sprite.from(source)` or `new Sprite(Texture.from(source))`; `new Sprite(source)` draws nothing. Show another region with `sprite.texture = new Texture({ source, frame: new Rectangle(...) })`, or create the texture with `dynamic: true` and call `texture.update()`. After drawing into a source canvas, call `texture.source.update()`. Rotate/scale about a point with `origin`; `pivot` also moves the object; `anchor` (0–1) shifts only the texture.
- `AnimatedSprite`: `animationSpeed` is frames per 60 fps tick (12 fps is `0.2`), needs `autoPlay: true` or `play()`. Call `play()` after each `anim.textures = ...` swap; replay a finished one-shot with `gotoAndPlay(0)`.
- Text systems (three, with tradeoffs):
  - `Text`: high-quality styled raster text via the browser text engine, then to a texture. Use for detailed font control (drop shadows, gradients, alignment) and occasional changes. Avoid for per-frame changes or hundreds of instances. Default fill is black, invisible on the default black background — set `fill`. Raise `style.padding` when a stroke or drop shadow is clipped.
  - `BitmapText`: ultra-fast, GPU-optimised, draws from a pre-baked bitmap font atlas, bypassing rasterisation. Use for HUDs, score counters, timers, lots of dynamic text, many instances. Requires a registered bitmap font: `BitmapFont.install(...)` or `Assets.load(...)` of a BMFont / AngelCode export. Strings changing every frame (score, timer, FPS) go in `BitmapText`; each `Text` change redraws a canvas and re-uploads it.
  - `HTMLText`: richly formatted HTML inside the scene via SVG `foreignObject`. Use for `<b>` / `<i>` / `<span>`, emoji, RTL, links, document-like layout. Avoid for pixel-perfect performance or hundreds of blocks. Fonts must come through `Assets.load({ src, data: { family } })`; `HTMLText` sees only fonts loaded this way.
  - `SplitText` / `SplitBitmapText`: split text into individually manipulable segments (lines, words, characters) for per-character / per-word animations.
- Graphics (for completeness, from skill router, not a doc fetched): shape first, then style — `new Graphics().rect(0, 0, 100, 50).fill(0xff0000).stroke({ width: 2, color: 0x000000 })`; `beginFill` / `drawRect` / `lineStyle` are v7. `FillGradient` takes an options object, every colour stop set before the first draw, `textureSpace: 'global'` for pixel coordinates (default `'local'` is 0–1 across the shape). Draw-time transforms apply in call order, reverse of Canvas 2D. Stroke `alignment` is `1` inside, `0` outside (inverted from v7). Animate a stable `Graphics` by its transform; `clear()` and redraw every frame re-tessellates.

## 8. Rendering / render graph

- Renderers draw the scene to a canvas using WebGL/WebGL2, WebGPU, or Canvas 2D. All inherit a common base with `.render()`, `.resize()`, `.clear()`, and shared systems for canvas management, texture GC, and events.
- `renderer.render(container)` draws a Container to the screen; options form `renderer.render({ container, clear, transform, target })`. `target` is a separate render destination (e.g. a `RenderTexture`). `renderer.generateTexture(displayObject)` creates a texture from any display object.
- Render targets: every texture rendered to gets a `RenderTarget` behind the scenes. Create one for multiple colour attachments, explicit depth/stencil, or per-attachment load/store behaviour. Attachments mirror WebGPU render-pass descriptors. One draw can write several colour attachments (colour, velocity, object ids) in a single pass; each attachment is written only if the fragment shader has an output at its location.
- Advanced render-target features fetched (first 499 lines): mip-level rendering (`mipLevel`), layered rendering (`layer`: array layer / cube-map face / depth slice), `flipY` (texture renders are stored Y-down; 3D UV conventions read upside down), depth-only targets (`colorTextures: 0, depth: true`; formats `stencil8`, `depth16unorm`, `depth24plus`, `depth24plus-stencil8`, `depth32float`, `depth32float-stencil8`), binding via `renderer.renderTarget.bind / push / pop / getBindState`, copying via `copyToTexture` / `copyDepthTexture`.
- What was NOT fetched as a v8 2D "render graph": the v8 docs use systems / pipes / render targets, not a single RenderGraph API in the pages read. The 3D docs use a different vocabulary: "How a frame renders" (passes a view runs each frame, which pass draws a mesh, settings that make the view compile new shaders) and `View3D#passes` / `Pass3D` / `RenderPassBit` (see 3D llms.txt). Do not conflate the two; see 04-limits-unknowns.md.
- Texture lifecycle: `Texture` stores the information representing an image or part of an image; `TextureSource` is the GPU backing. `generateTexture`, `RenderTexture.create({ width, height, mipLevelCount, autoGenerateMipmaps })`.
- HTMLSource (experimental): render live HTML elements / DOM snapshots as PixiJS textures via `HTMLSource` / `ElementImageSource`, using experimental HTML-in-Canvas browser APIs.
- GC: Garbage Collection guide exists in llms.txt (core-concepts-6); content not fetched. Performance Tips guide exists (core-concepts-7); content not fetched beyond skill router (`performance.md`: FPS, draw calls, memory leaks, first-frame hitches, `GCSystem`, `PrepareSystem`, render groups, `cacheAsTexture`, batching order, culling, pooling, filter/mask cost).

## 9. PixiJS 3D surface (from pixijs-3d skill + 3D llms.txt — summary only; lane A owns 3D depth)

- `View3D` is an ordinary 2D display object on the Pixi stage rendering a 3D scene into its rectangle. Scene hangs from `view.root` (a `Container3D`); the view owns its `camera`; lights are nodes; the Pixi application ticker is the frame loop.
- Quick-start shape: `new View3D({ autoResize: true, shadowQuality: 'medium', environment: { skyColor, groundColor, intensity: 0.7 } })`, `app.stage.addChild(view)`, lights/meshes/models under `view.root`, `view.camera.position.set(...)`, `view.camera.lookAt(...)`, `new OrbitCamera({ view, enableDamping: true })`, per-frame work on `app.ticker`.
- Nodes: `position`, `rotation` (Euler radians), `quaternion`, `scale`, `visible`, `lookAt(point)`, `addChild`, `traverse(callback)`, `getLocalBounds()`. Constructors take one options object; same values are plain properties afterwards.
- Camera: `view.camera` is a `Camera3D`; `fov` is vertical field of view in degrees (default 60), `near` 0.1, `far` 1000, `mode` `'perspective'` or `'orthographic'` with `orthographicSize` (half the view's width in world units, default 5).
- Facing: cameras and lights look down local -Z; meshes and glTF models face +Z. A `DirectionalLight` is aimed by `rotation` (or `lookAt`), not a target. `PlaneGeometry` lies in XY with a +Z normal; rotate -π/2 around X for a floor.
- Primitives: `CubeGeometry({ width, height, depth })`, `SphereGeometry({ radius })`, `CylinderGeometry({ radiusTop, radiusBottom, height })` (no `radius`), `ConeGeometry({ radius, height })`, `CapsuleGeometry({ radius, height })` (height includes caps), `TorusGeometry({ radius, tube })` (lies in XZ), `PlaneGeometry({ width, height })`, `IcosahedronGeometry({ radius, detail })`. Each also takes segment counts.
- Lighting: `DirectionalLight`, `PointLight`, `SpotLight`, `AmbientLight` are nodes. Soft fill from the view's `environment`: `{ skyColor, groundColor, intensity }` for a hemisphere, or a `CubeTexture` (`.cubemap` or `.hdr` via `Assets.load`) for image-based lighting. Shadows: `castShadow` on the light, `castShadow` / `receiveShadow` on meshes, `shadowQuality` (`'low' | 'medium' | 'high' | 'ultra'`) on the view. A view shades 32 lights and 16 shadow maps.
- Materials: `Material3D` is PBR (`baseColor`, `metallic`, `roughness`, `baseColorTexture`, `alphaMode`, `alpha`); glow is opt-in `emissive: { color, strength }`, never a plain colour. `FlatMaterial` is unlit. Custom looks come from shader bits in `extraBits`, not a ShaderMaterial class. `material.clone(options)` copies with options changed or bits added.
- Models: `Assets.load<Scene3DSource>(url)` then `new Model3D({ source })`. Animation clips play through `model.player`. Models from one source share materials; `model.materials` gives one model its own.
- Extras (`@pixi/3d/extras`): `OrbitCamera`, `FPSCamera`, `ParticleSystem3D`, `BloomEffect`, `SsaoEffect`, `TiltShiftEffect`, `MotionBlurEffect`, `TintEffect`, `FxaaEffect`, `ToonMaterial`, `PortalPass`, `PortalMaterial`, `dissolveBit`.
- Many copies: `BatchedMesh3D` draws thousands of instances in one call (`setMatrixAt`, `setInstanceDataAt`). Separate `Mesh3D` nodes batch into instanced draws on their own when they share a geometry, the same kind of material, and the same texture sources.
- 2D over 3D: HUD text, buttons, sprites are ordinary Pixi objects added to the stage after the view. `view.worldToScreen(point)` places a 2D label at a 3D position (always draws over the 3D). For a picture inside the scene that walls can hide, use `Sprite3D({ texture, height, billboardMode, parent: view.root })`.
- Renderers: `app.init` uses WebGL unless `preference: 'webgpu'`; nothing else in the code changes. MSAA is `app.init({ antialias: true })`; `View3D` has no `antialias` option. No enums: `shadowQuality`, `alphaMode`, `mode` are string literals.
